# LingoLog 多端同步后端

一个人、几台设备、免费。没有账号体系——**同步码就是凭证**。

```
手机浏览器  ─┐
             ├─→  Cloudflare Worker  ─→  D1（一行一个同步码）
电脑浏览器  ─┘        /sync                rev + 整包 JSON 快照
```

## 为什么不用 KV

Cloudflare 免费层里 KV 更"顺手"，但对这个场景有两个硬伤：

| | KV | D1 |
|---|---|---|
| 写入额度（免费） | **1,000 次/天** | **100,000 行/天** |
| 一致性 | 最终一致，全球传播最长约 60 秒 | 强一致（单主库） |
| 条件更新 | 不支持 | 支持 `WHERE rev = ?` |

第二行是决定性的。KV 的最终一致会造出一条真实的数据丢失路径：

> 手机上复习完 → 推送成功 → 立刻打开电脑 → 电脑的读请求落到还没收到新值的边缘节点 →
> 读到旧数据 → 电脑再推送 → **把手机的新记录覆盖掉**。

KV 没有条件更新，所以服务端拦不住这一下。D1 有。加上写额度差 100 倍，选 D1 没有悬念。

## 部署（浏览器里点，不需要装 CLI）

### 1. 建 D1 数据库
Cloudflare 控制台 → **存储和数据库 / Storage & Databases** → **D1 SQL Database** → 创建，
名字随意，例如 `lingolog-sync`。

进去后打开 **控制台 / Console**，把 `schema.sql` 的内容粘进去执行。

### 2. 建 Worker
**Workers & Pages** → 创建 → **Worker** → 起个名字 → 部署（先用默认的 Hello World 代码）。

部署后点 **编辑代码 / Edit Code**，把默认内容整个删掉，粘贴 `worker.js`，再 **部署**。

> 兼容性日期（Compatibility date）用默认值即可。
> 这个脚本只用标准 Web API + D1，不依赖任何 npm 包。

### 3. 绑定数据库（关键一步）
Worker → **设置 / Settings** → **绑定 / Bindings** → 添加 → 选 **D1 database**：

- 变量名（Variable name）必须是 **`DB`**，不能改
- D1 数据库选第 1 步建的那个

保存后**重新部署一次**（绑定变更需要新版本生效）。

### 4. 验证
浏览器打开 `https://你的worker地址.workers.dev/health`，应看到：

```json
{ "ok": true, "hasDb": true, "tableOk": true, "error": null, "time": "..." }
```

`ok:false` 就是绑定没生效——回去看变量名是不是 `DB` 这个词。

### 5. 记下地址
形如 `https://lingolog-sync.你的子域.workers.dev`。填进 App 的「个人中心 → 多端同步」。

## 免费额度

按官方定价页（2026-09 核对）：

- **Workers**：100,000 请求/天，10ms CPU/次 —— 个人用远够
- **D1 免费层**：5,000,000 行读/天、**100,000 行写/天**、5 GB 存储

⚠️ **注意**：D1 从 **2026-09-01** 起开始**硬性执行**免费层限额（此前只记录不拦截）。
超了当天会直接返回错误，次日 UTC 0 点重置。对你的量级来说碰不到，但知道一下。

## 安全边界

**已经做到的**

- 同步码 **26 位 Crockford Base32 ≈ 130 bit 熵**，枚举不可行
- 库内只存 **SHA-256(同步码)**，不存明文。库泄露 ≠ 同步码泄露
- 同步码走**请求头**，不走 URL —— URL 会进各级访问日志，请求头不会
- 强制 **HTTPS**（客户端会拒绝 http 地址）
- 服务端兜底剥离 `settings.customApiKey`，老客户端误传也不会落库
- 单包上限 1 MB，超了拒绝而不是截断

**你要知道的**

- **同步码 = 密码。** 谁拿到它，谁就能读和写你的数据。不要发到群里、不要贴进截图。
- **数据是明文存的。** Cloudflare 那端看得到内容（不加密）。为此做端到端加密属于过度设计——那要多一套密钥管理，而你的数据是英语学习卡，不是密钥库。
- CORS 是 `*`。这里安全，因为认证凭证是同步码本身、不走 Cookie，所以不存在别的站点"借"你身份的问题。
- **丢了同步码 = 云端数据找不回。** 没有找回流程，这是刻意的。建议把同步码和导出的 JSON 备份一起存一份。

## 同步机制与说明

1. **已全面接入客户端**：点击「我的」界面头像或「多端登录认证」按钮即可唤起同步弹窗；应用启动时会自动检测云端版本差并拉取更新。
2. **冲突手动选择**：两台设备都发生修改且版本冲突时，服务端返回 409，由用户自主选择「以云端版本为准」还是「覆盖更新云端」。
3. **轻量防抖同步**：应用启动时拉取 + 手动触发即时拉取/推送，既避免频繁请求浪费额度，又保障多端一致。
4. **`customApiKey` 永不上传云端**：API 密钥只保存在各设备本地浏览器的 localStorage 中，绝不随卡片同步上传，最大程度保障资产安全。
